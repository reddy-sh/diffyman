## Done in Phase 1

- **Ignore rules, schema 0.2.0** ([spec §7.2.1, §7.3](spec/diff-document.md)): `ignore.regex` masks each match with a per-pattern placeholder (a masked value still differs from a missing one), with deterministic limits (16 patterns, 1024 characters, 50000 NFA units) and a new `invalid-regex` error. `ignore.blankLines` turns blank-only changes into the new `ignored` op kind: not a change, not counted in stats, never a hunk of its own, and left out of the similarity denominator, so blank-only differences are `identical`. Re-blessing changed only `schemaVersion` and `id` in 74 of the 75 existing golden files; the other one, `text/018`, now masks its timestamps instead of being an `unsupported-option` error. Five new text cases (036–040); CLI, Python and WASM stay byte-identical on all 80 cases.
- **Canonical JSON writer:** documents are serialized straight to RFC 8785 text without a `serde_json::Value` tree. Two 32 MB inputs with a 107 MB document now peak at 0.6 GB footprint instead of 2.5 GB, with byte-identical output.
- **Moved-block detection** (`text.moves@1`, [moves spec §4](spec/text-granularity-and-moves.md)): pure moves (with indentation changes) and edited moves, `detectMoves: true` is supported, and moves never change hunks. On the 41 labelled cases: precision 1.00 and recall 1.00 (36 of 36 labels), kind accuracy 1.00, exact boundaries 0.81, no moves in the 9 negative cases. The conformance runner now gates on these metrics. Pure pieces of one moved block with an edited line inside are joined into one edited move (moves spec §4.3 step 4, case `moved/041`). Work is bounded by deterministic limits (`moves-skipped-limit`); the edited search compares small segment pairs first, so large unrelated churn no longer switches it off.

- **Line-diff core** ([ADR 0006](adr/0006-line-diff-library.md)): `text.histogram@1` and `text.myers@1` run on `gix-imara-diff` 0.3.3; Histogram has a deterministic work budget with a Myers fallback (200k swapped line pairs: 0.46 s instead of 33 s). Inputs over 256 MiB per side give `limit-exceeded`.
- **Spec alignment:** one source of truth for output shapes, options and warning codes ([diff-document.md](spec/diff-document.md)); LF, CRLF and lone CR all end a line; default granularity `line`.
- **Corpus:** 40 text cases (invalid UTF-8, UTF-16, mixed and lone-CR line endings, long lines, word/char/smart granularity) and 41 moved-block cases; 81/81 pass in strict conformance, which CI now enforces.
- **Canonical writer:** a direct RFC 8785 writer replaced the intermediate JSON tree; peak memory on a 1M-line, 107 MB result fell from 2.5 GB to 0.6 GB.
- **Large-file mode** ([ADR 0006, large-file mode](adr/0006-line-diff-library.md#large-file-mode)): through the CLI, the 1 GB log pair now takes 1.9 s and 536 MB peak footprint (was 8.5 s and 4.5 GB), the 100 MB pair 0.14 s and 52 MB (was 0.52 s and 416 MB), 5 M copies of one line 0.48 s and 205 MB (was 0.90 s and 561 MB), and a 1 GB file against itself 0.65 s and 58 MB (was 7.3 s and 4.4 GB). Outputs are byte-identical: no golden file was re-blessed, CLI, Python and WASM agree on all cases, and the large outputs match the previous build. How: memory-mapped input (`--no-mmap` to read), a 4-byte-per-line index instead of line records, byte-identical inputs decoded once, the common prefix and suffix trimmed before interning, keys borrowed from the text unless an ignore option normalizes them, both sides decoded and hashed on two threads (native only), and the canonical JSON and its `id` streamed instead of built as strings. `spikes/line-diff-bench/cli-bench.sh` reproduces the numbers with the real CLI.

- **Type detection and binary diff, schema 0.3.0** ([ADR 0009](adr/0009-type-detection-and-binary-diff.md), [spec §16–§18](spec/diff-document.md)): new crates `diffyman-detect` (`detect.sniff@1`: text or binary from the content only, UTF-8 and UTF-16 validity, NUL and control bytes in the first 8000 bytes; media type from `infer` 0.22.0 magic numbers or a small extension table) and `diffyman-adapter-binary` (`binary.bytes@1`: common prefix and suffix, byte-level Myers up to 64 KiB under a global work budget, FastCDC chunks with BLAKE3 for larger inputs). New kind `binary` with `bytes[]` ranges and `stats.bytes`, a new `adapter` option (`auto`, `text`, `binary`), and warnings `binary-fallback` and `bytes-coarse-limit`. Under `auto`, inputs that are not UTF-8 give a binary document instead of an `invalid-utf8` error. Re-blessing changed only `schemaVersion`, `id`, `options.adapter` and `stats.bytes: null` in 78 of the 81 existing golden files; the other three changed `mediaType` by detection (`text/csv`, `application/yaml`, and `application/octet-stream` for the Latin-1 side of 021). `text/021` and `text/022` now pin `adapter: "text"`. 16 new `binary/` cases (97 in all) pass strict conformance and `check_binary_expected.py`, which rebuilds each right input from the ranges; CLI, Python and WASM agree on all of them. Through the CLI a 256 MiB pair with 4096 scattered one-byte edits takes 0.8 s, and 64 hard 30 KiB regions stay within the budget (0.13 s).
- **Folders and archives, schema 0.3.0** ([ADR 0010](adr/0010-folders-and-archives.md), [spec §6.8, §19](spec/diff-document.md)): new crate `diffyman-adapter-tree` (`tree.entries@1`) and kind `tree`: one entry per path (`added`, `removed`, `modified`, `unchanged`, `moved`, `typeChange`) with both sides' type, size, SHA-256 and link target, renames by equal content (same last component first), and an embedded child document (text, binary or a nested tree) for each modified file, within `tree.childBudget`. Folders are walked with `ignore` 0.4.34 (`.gitignore`/`.ignore` on request, links never followed by default) behind the `fs` feature; zip (`zip` 9.4.1), tar (own strict reader), tar.gz (`flate2`, pure Rust) and tar.zst (`ruzstd`) are read from memory, never extracted, in every binding including WASM. Limits end in `limit-exceeded` (entry count, forged zip64 counts, path text) or `tree-limit` with status `partial` (compression ratio over 100×, 4 GiB content budget per side across nesting); unsafe, non-UTF-8, duplicate, encrypted and unreadable entries get their own warnings. New `adapter: "tree"` and `tree` options; `diffyman diff` takes folders and prints a name-status list. Re-blessing changed only `id`, `options.tree` and `stats.tree: null` in all 97 existing golden files; 26 new `tree/` cases (123 in all) pass strict conformance, CLI and Python agree byte for byte on all of them and WASM on the 14 without a folder input. A folder of 1,167 files (1.1 GiB) diffs against a copy in 1.7–2.0 s with about 5 MB peak footprint. The WASM package is 634 KB brotli.
- **Fuzzing fixes:** canonical JSON now rejects a float of magnitude 2^53 up to 10^21 (ECMAScript prints it as an unsafe integer literal), so canonical text is always a fixed point (spec §5); `jcs_roundtrip` no longer tolerates that case. The `smart` noise check and whitespace merging in inline refinement are linear instead of spans × tokens, with byte-identical output.
- **CLI** ([reference](cli.md)): `diffyman diff` (files, folders and archives, detected automatically) with `--format text|unified|json|html|summary`, `--json`, `--pretty`, `--json-stream` (one canonical JSON line per hunk, byte range or tree entry), `-o`, `--color auto|always|never` following `NO_COLOR`, `--options` plus flags for the common options (a flag replaces the file's value; the result goes through the engine's option rules). The text format shows control and bidi characters as markers; the unified format is a byte-exact patch, and for two folders one patch per modified text file. `diffyman dir` (two folders), `schema`, `formats` (table or JSON, IDs checked against provenance), `textconv` (the text, or each line's comparison key, for git's textconv) and `git install` (prints the difftool and textconv config; writes only with `--global` or `--local`). Exit codes 0 identical, 1 different or partial, 2 error. The summary renderer now handles tree documents. 13 integration tests run the binary: every command, exit codes, color and `NO_COLOR`, JSON equal to the corpus, golden outputs for five corpus cases (text, invisible characters, binary, folders, zip), `git difftool` and textconv end to end against a temporary git configuration, and a check that the help text in `docs/cli.md` is current. No golden `expected.json` changed.
- **Move detection edge cases and inline masks** ([moves spec §3.2, §4](spec/text-granularity-and-moves.md), still `text.moves@1` and `text.refine@1`, which are unreleased): move keys apply `ignore.regex` masks, so a block that moved and got new timestamps is a pure move. Each `replace` op is aligned again by move key; lines that only changed indentation or terminator are in place, and the runs between them are sub-ops for rule 4.1.4, so a whole-file LF to CRLF conversion under whitespace `none` no longer hides moves (the old spec claim that a terminator change never prevents a move is now true). Lines over 256 graphemes are compared by their common prefix and suffix plus an exact bit-parallel distance of the remainders (at most 4096 graphemes each, under a 32M-step budget that ends in `moves-skipped-limit`), so a one-character edit in a long line keeps its block. Edited moves need a word similarity of at least 0.60, so a config section whose values all changed (block similarity 0.93, word similarity about 0.5) is no longer a move. Inline refinement treats each regex match as one token, so masked values get no spans. The `moves-skipped-limit` message now covers detection that was cut short. No existing golden file changed; 5 new cases (`moved/042`–`045`, `text/041`), 128 in all. On the 45 labelled cases: precision 1.00, recall 1.00 (39 of 39), kind accuracy 1.00, exact boundaries 0.82, no moves in the 10 negative cases.
- **Review fixes** (still schema 0.3.0 and the unreleased `@1` IDs; spec §17, §19.4–§19.6 updated): move detection now reads only the lines of change ops (one gap line per unchanged run), so its memory follows the changed lines instead of the file length: 10 M lines with one change and `--detect-moves` peak at 102 MB instead of about 5 GB, 5 M copies of one line at 52 MB instead of 2.5 GB, and 20 M lines through WASM no longer run out of memory; a test checks the moves equal those of the whole-file run. The binary diff chunks a changed region that is still too large for byte alignment again at 1 KiB and 256-byte average chunks, then compares it position by position when that keeps at least half of it, so edits closer together than one chunk keep their own ranges (128 KiB with 30 eight-byte overwrites: 30 exact ranges, similarity 0.998, was one coarse range at 0.06). Zip entries whose bytes overlap an earlier entry's are not read (`tree-limit`), so a stream shared by many central directory entries is inflated once: a 1.9 MB pair that inflated about 16 GiB in 16.7 s is now bounded by its own size, and a pair of 2000 entries sharing one 64 MiB stream takes 0.5 s. Child contents count against the 4 GiB per-side content budget, a nested tree sets its own size aside before its children use `tree.childBudget`, and no child is computed once the budget is below the smallest possible child: on a 17 KB pair of 16-way nested zips, `childBudget` 1 takes 0.0 s (was 26.6 s on the reported pair), the defaults 1.1 s with the 16 MiB budget filled, and budgets of 64 KiB and 4 MiB 0.3 s each instead of 3.0 s and 8.0 s with nothing embedded; `maxDepth` 16 is bounded by the content budget (6 s, was 69 s on the reported pair). The CLI creates `-o` only after the inputs are compared and refuses an output that is one of the inputs (also through another path or a hard link), so `diff a b -o a` and `textconv f -o f` no longer destroy the input or crash on a truncated memory map. New cases `binary/017-dense-overwrites` and `tree/027-zip-overlapping-entries`; no existing golden file changed (130 cases, strict conformance, CLI, Python and WASM byte-identical).
