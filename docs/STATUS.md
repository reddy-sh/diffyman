## Done in Phase 1

- **Ignore rules, schema 0.2.0** ([spec §7.2.1, §7.3](spec/diff-document.md)): `ignore.regex` masks each match with a per-pattern placeholder (a masked value still differs from a missing one), with deterministic limits (16 patterns, 1024 characters, 50000 NFA units) and a new `invalid-regex` error. `ignore.blankLines` turns blank-only changes into the new `ignored` op kind: not a change, not counted in stats, never a hunk of its own, and left out of the similarity denominator, so blank-only differences are `identical`. Re-blessing changed only `schemaVersion` and `id` in 74 of the 75 existing golden files; the other one, `text/018`, now masks its timestamps instead of being an `unsupported-option` error. Five new text cases (036–040); CLI, Python and WASM stay byte-identical on all 80 cases.
- **Canonical JSON writer:** documents are serialized straight to RFC 8785 text without a `serde_json::Value` tree. Two 32 MB inputs with a 107 MB document now peak at 0.6 GB footprint instead of 2.5 GB, with byte-identical output.
- **Moved-block detection** (`text.moves@1`, [moves spec §4](spec/text-granularity-and-moves.md)): pure moves (with indentation changes) and edited moves, `detectMoves: true` is supported, and moves never change hunks. On the 41 labelled cases: precision 1.00 and recall 1.00 (36 of 36 labels), kind accuracy 1.00, exact boundaries 0.81, no moves in the 9 negative cases. The conformance runner now gates on these metrics. Pure pieces of one moved block with an edited line inside are joined into one edited move (moves spec §4.3 step 4, case `moved/041`). Work is bounded by deterministic limits (`moves-skipped-limit`); the edited search compares small segment pairs first, so large unrelated churn no longer switches it off.

- **Line-diff core** ([ADR 0006](adr/0006-line-diff-library.md)): `text.histogram@1` and `text.myers@1` run on `gix-imara-diff` 0.3.3; Histogram has a deterministic work budget with a Myers fallback (200k swapped line pairs: 0.46 s instead of 33 s). Inputs over 256 MiB per side give `limit-exceeded`.
- **Spec alignment:** one source of truth for output shapes, options and warning codes ([diff-document.md](spec/diff-document.md)); LF, CRLF and lone CR all end a line; default granularity `line`.
- **Corpus:** 40 text cases (invalid UTF-8, UTF-16, mixed and lone-CR line endings, long lines, word/char/smart granularity) and 41 moved-block cases; 81/81 pass in strict conformance, which CI now enforces.
- **Canonical writer:** a direct RFC 8785 writer replaced the intermediate JSON tree; peak memory on a 1M-line, 107 MB result fell from 2.5 GB to 0.6 GB.
- **Large-file mode** ([ADR 0006, large-file mode](adr/0006-line-diff-library.md#large-file-mode)): through the CLI, the 1 GB log pair now takes 1.9 s and 536 MB peak footprint (was 8.5 s and 4.5 GB), the 100 MB pair 0.14 s and 52 MB (was 0.52 s and 416 MB), 5 M copies of one line 0.48 s and 205 MB (was 0.90 s and 561 MB), and a 1 GB file against itself 0.65 s and 58 MB (was 7.3 s and 4.4 GB). Outputs are byte-identical: no golden file was re-blessed, CLI, Python and WASM agree on all cases, and the large outputs match the previous build. How: memory-mapped input (`--no-mmap` to read), a 4-byte-per-line index instead of line records, byte-identical inputs decoded once, the common prefix and suffix trimmed before interning, keys borrowed from the text unless an ignore option normalizes them, both sides decoded and hashed on two threads (native only), and the canonical JSON and its `id` streamed instead of built as strings. `spikes/line-diff-bench/cli-bench.sh` reproduces the numbers with the real CLI.

Under `auto`, inputs that are not UTF-8 give a binary document instead of an `invalid-utf8` error. Re-blessing changed only `schemaVersion`, `id`, `options.adapter` and `stats.bytes: null` in 78 of the 81 existing golden files; the other three changed `mediaType` by detection (`text/csv`, `application/yaml`, and `application/octet-stream` for the Latin-1 side of 021). `text/021` and `text/022` now pin `adapter: "text"`. 16 new `binary/` cases (97 in all) pass strict conformance and `check_binary_expected.py`, which rebuilds each right input from the ranges; CLI, Python and WASM agree on all of them. ## Done in Phase 2

Every binding follows [ADR 0007](adr/0007-binding-strategy.md): one native call that returns the engine's canonical JSON unchanged, typed wrappers in the host language generated from the JSON Schema, and the engine's error rule (invalid options or an unreadable path raise; problems with the inputs are a document with `status: "error"`). No binding has diff logic of its own.

- **Python** ([README](../bindings/python/README.md)): PyO3, one abi3 wheel for CPython 3.11+, `diff`, `diff_document` and generated `TypedDict` types (`mypy --strict`); the GIL is released during a diff. 470 tests pass; `uv.lock` pins the development tools and their dependencies.
- **Node.js** ([README](../bindings/node/README.md)): a napi-rs addon (`@diffyman/node`, Node.js 22+) with `diff`, `diffDocument`, `diffPaths` and `...Async` variants on the libuv thread pool, `DiffymanError` with the engine's `code`, and TypeScript types generated from both schemas. A panic inside the engine is caught (on the thread pool too) and thrown as an `Error` with code `internal` instead of aborting Node.js. 870 `node:test` tests, including the whole corpus through all four entry points.
- **Java** ([README](../bindings/java/README.md)): JNI, Java 17+, no runtime dependencies, `Diffyman.diff` and `diffPaths` returning the canonical text, `DiffymanException` with a `code()`, the native library loaded from a system property, `java.library.path` or the jar; JUnit 5 tests over every corpus case through both entry points.
- **C ABI** ([README](../crates/diffyman-ffi/README.md)): `diffyman-ffi` with a cbindgen header, status codes, ownership rules and no panic across the boundary; Rust tests over the corpus and a C test program under AddressSanitizer and UndefinedBehaviorSanitizer; calling patterns for Go and C#.
- **Browser** ([React README](../bindings/wasm/react/README.md), [example app](../examples/amplify-react)): `@diffyman/react` runs the WASM build (618 KB brotli, 462 KB without archives) in a Web Worker behind `useDiff`, with cancellation of stale requests, and a static Vite + React app renders a document side by side.
- **Conformance** (`tests/conformance/run_bindings.py`): CLI, Python, WASM, WASM without archives, Node.js, Java and C give byte-identical documents (provenance removed) on all 216 corpus cases, all equal to `expected.json`, and on the 68 line-only variants: 3022 runs on macOS arm64, every bytes and paths entry point included. The build without archives refuses exactly the 23 cases that need them with `unsupported`; folder inputs are skipped only where an API takes bytes.
- **Publication review:** the Node.js, React and Python packages carry `LICENSE-MIT` and `LICENSE-APACHE` (copies of the root files, checked by a test in each; PEP 639 `license-files` for the wheel and sdist); the Maven POM marks the two licenses as a choice, has full `scm` connections and skips `mvn deploy`; package homepages point to the repository; [ADR 0005](adr/0005-license.md) lists the test-only license exceptions (JUnit 5 under EPL-2.0, PSF-2.0 and MPL-2.0 build tools); `.gitignore` covers `.mypy_cache/`, `coverage/`, `*.tsbuildinfo` and `npm pack` tarballs. No package has been published.
- **Quickstarts** ([docs/quickstart](quickstart/cli.md)): CLI, Python, Node.js, Java, browser and React, and C, each with build-from-source steps, an example that diffs two files and prints the status and the changed lines, options, rendering, error handling and links to the spec. The README has a table of them. `docs/quickstart/check_examples.py` runs every code block (69 in all: files, commands, expected output, and for the browser a Vite build, a strict type check and a render of the component with the real WASM engine); a block without a check directive is an error. The built browser page was also loaded in Chromium with two picked files and showed the expected lines.

## Moved to later phases

- **Phase 3 (local platform):** `childRef`, for services that store child documents apart from their parent.
- **Phase 3b (packaging):** license files in the wasm-pack package `diffyman-wasm` (the Node.js, React, Python and Java packages have them) before any registry release.
- **Phase 4 (formats):** legacy text encodings (for example Latin-1 on request); bzip2, xz and 7z; the content of modified archive entries in the unified format and the HTML report (today only for two folders: archive entries would need a second listing of each archive, as costly as the comparison, unless the tree adapter can read one entry by path or the engine hands out child contents while it has them).
- **Later tuning (no phase fixed):** a binary diff whose chunk alignment leaves a changed region over 64 MiB goes straight to the position-by-position step (exact for overwrites, flagged `bytes-coarse-limit`), as in a 256 MiB pair with 4096 scattered one-byte edits; under `ignore.whitespace` `all`, `moved/027` and `moved/046` lose their move and 046 gets a short false one (not yet investigated); joining an edited line above a pure piece (moves spec 4.3 step 4 only walks down), so a block whose first lines changed can come out as an edited and a pure move instead of one; `--no-mmap` reads a regular file whole before the 4 GiB binary limit refuses it (by design: it gives the same error document as the mapped default; `--max-input-size` bounds it).
